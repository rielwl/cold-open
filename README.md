# Cold Open

**Deals you something to be curious about, then starts a clock.**

👉 **Try it: https://rielwl.github.io/cold-open/**

Press **Deal** and a card arrives, styled as an airmail letter. The app picks
the subject and keeps time. The reading, notes and talking happen on paper,
away from the screen.

---

## Two ways to play

### Sprint — on your own

You get an unfamiliar subject from Wikipedia and five **guiding questions**,
one for each card of a short talk:

> what it is → how it works → why it matters → the twist → what's still open

Research it against the clock, then give a talk of under five minutes.
**Talkable** (on by default) skips subjects too thin to fill five minutes.

### Paper — for two of you

You get an open-access research paper and one of 12 **reading lenses**. Each
lens gives you something specific to read for, e.g. "Mark the exact sentence
where the data stops and the interpretation starts."

- **Date night** (on by default) sticks to papers two non-specialists can follow.
- **Copy invite** gives you a message to send the other person.
- **Print handout** gives you a sheet each, with the lens, questions to talk
  about afterwards, and room for notes.

### Handy to know

- **Familiarity**: tick the areas you already know. You can then deal cards
  "far from what I know" or "close to home".
- **Pass** on a card and say why. Why you passed decides when it can come back:
  "already know it", "looks thin" and "too close to work" keep it away for six
  months, "not in the mood" for two weeks.
- **Fix this** under any card corrects its score or subject area if it looks
  wrong. See [Correcting a rating](#correcting-a-rating).
- **Space** deals a card. Once the clock is running, it pauses and resumes it
  instead.
- **Log**: what you finish or pass on is saved in this browser only. Use
  **export** / **import** to move it to another device.

## Running it yourself

It's a single static page with no build step and no dependencies. Open
`index.html` in a browser, or serve the folder:

```sh
npx serve .              # or: python -m http.server 8000
```

### What's in the repo

| Path | What it is |
|---|---|
| `index.html` | The whole app: one page with inline CSS and JavaScript. |
| `corpus.js` | The deck of cards (~6 MB), generated by `tools/`. Committed so the page works with no network access. |
| `prompts.js` | The Sprint questions and Paper lenses, as plain data. Edit and reload; no rebuild. |
| `tools/` | Scripts that build the deck, plus the hand-reviewed ratings files. |
| `docs/airmail-design.md` | The visual design spec (colours, type, spacing, states). |
| [`NEXT-STEPS.md`](NEXT-STEPS.md) | Where things stand, known limits and the backlog. Start here after a break. |
| [`AGENTS.md`](AGENTS.md) | House rules for anyone changing the code, human or AI. |

### Checks

```sh
node --test tools/*.test.mjs
```

These run on every push and pull request. They check the tools' helpers, that
the app script parses, that the deploy ships every file the page loads, and
that the deck has the shape the app expects. They don't click through the UI;
[AGENTS.md](AGENTS.md#checking-a-change) has the short manual checklist.

### Deploying

Push to `main`. GitHub Actions (`.github/workflows/pages.yml`) publishes
`index.html`, `corpus.js` and `prompts.js` to GitHub Pages; nothing in `tools/`
goes live. The **Actions** tab shows each run, and **Run workflow** there
redeploys by hand.

## Privacy and security

- **No accounts, no tracking, no server.** The page is three static files. Your
  settings, log and rating fixes live in your browser's `localStorage` and go
  nowhere unless you export them.
- **Nothing is fetched after the page loads.** The deck ships with the page. The
  only third party is Google Fonts, which serves the typefaces.
- **Locked down by a Content-Security-Policy** (in `index.html`). Only the page's
  own scripts can run, and it can't fetch or send anything. So even an injected
  script or a malicious import file can't load code or leak data. When you edit
  the inline script, its hash in the policy has to change too; the checks print
  the new value.
- **No secrets in the repo or the live site.** API keys are only used by the
  build tools, read from your environment (see below) and never committed.
  `.env` files are git-ignored for the same reason.
- **Traffic.** GitHub Pages serves and absorbs it; there's nothing behind the page
  to overload and nothing that costs money per visit.

## The deck

**5,502 subjects and 4,163 papers**, all drawn from real sources, not generated.

**Subjects** come from Wikipedia:

1. The [unusual articles](https://en.wikipedia.org/wiki/Wikipedia:Unusual_articles)
   list, from its themed subpages (`/Science`, `/Language`, `/Food`, …), so each
   entry keeps the volunteers' one-line blurb. Sports and pop culture are left out.
2. Featured articles under science, history, engineering and humanities
   headings. Warships, football and discographies are dropped.
3. Category top-ups for areas the featured list barely covers: chemistry,
   psychology, maths, medicine, physics and art.

**Papers** come from [OpenAlex](https://openalex.org): open-access research
articles in eLife, PLOS, the Royal Society journals, PNAS, *Psychological
Science*, *Journal of Economic Perspectives* and others. A citation band and a
title blacklist remove protocols, errata, genome announcements and methods
papers. Extra humanities, linguistics, history and archaeology papers are
added because the science journals barely cover them. Page counts and direct
PDF links come from OpenAlex too.

**Every card carries hand-reviewed labels**, kept in two committed files:

- `tools/paper_ratings.tsv`
  - how easy a paper is for two non-specialists, 0–3 (Date night deals 2s and 3s)
  - its real subject area (OpenAlex files the 1918 flu under maths, for example)
  - whether it reports its own data, so "find the effect size" isn't dealt for a
    theory paper
- `tools/topic_ratings.tsv`
  - whether a subject has five minutes of talk in it, 0–3 (Talkable deals 2s and 3s)
  - its real subject area

A score of `x` drops the card from the deck. Anything new without a label
scores 1, so it stays out of Date night and Talkable until someone labels it
(see [AGENTS.md](AGENTS.md#labelling-new-cards)).

Each subject card also shows a rough length (`brief` to `very long`), based on
the article's size.

### Correcting a rating

1. On the card, click **fix this** and change the score, the area, or (for
   papers) whether it reports its own data. The fix applies straight away on
   that device. Passing a card as **looks thin** also lowers its score by one.
2. To make fixes permanent for everyone, click **export fixes** under the log,
   then:

   ```sh
   node tools/enrich.mjs cold-open-fixes-2026-10-01.json   # folds them into the .tsv files
   git commit -am "Rating fixes" && git push
   ```

The full log export carries your fixes too, so importing it on another device
brings them across.

### Updating the deck

The usual loop, run from the repo root. Both scripts cache what they fetch
(`tools/*_cache.json`, not committed), so re-runs are quick.

```sh
node tools/extend.mjs     # optional: more subjects for thin areas + humanities papers
                          # ...label anything new (see AGENTS.md)...
node tools/enrich.mjs     # applies ratings, page counts and PDF links; writes corpus.js
```

**API keys (optional).** OpenAlex meters its API. Without a key you get about
$0.10 of calls a day; a free key from openalex.org gives $1. The scripts stick to
the cheap calls, so a full enrich is about 70 calls. For big rebuilds:

```sh
export OPENALEX_API_KEY=...            # PowerShell: $env:OPENALEX_API_KEY="..."
export CONTACT_EMAIL=you@example.com   # optional; sent to OpenAlex, NCBI and Wikipedia as your contact
```

These are read from the environment only. **Never commit them.**

<details>
<summary><b>Rebuilding the whole deck from scratch</b></summary>

Rarely needed. Run in order, from `tools/`. Each step writes JSON that the next
one reads. They call live APIs, so expect a few minutes.

```sh
python fetch_wiki.py     # candidate titles: unusual list + featured articles
python hydrate2.py       # extracts and article lengths
python unusual5.py       # themed oddity tables, with their curated blurbs
python topup.py          # extra subjects for the thin areas
python papers3.py        # open-access papers, classified by OpenAlex field
python build5.py         # writes tools/corpus.js
node extend.mjs          # more subjects for thin areas + humanities papers
node enrich.mjs          # ratings, page counts, PDF links; writes ./corpus.js
```

Stubs are kept out by a minimum article size: 10,000 bytes for oddities
(`build5.py`) and 9,000 for top-ups (`extend.mjs`). The talkability labels do
the real filtering.

</details>
